Fetch base: public repo — raw.githubusercontent.com: CDN-fronted, CORS-enabled, and updated the moment a build pushes the branch. private repo — raw.githubusercontent.com needs auth and sends no CORS header, and shields.io can't read the repo at all. The docs workflow (giellalt/.github docs.yml) copies the branch into this site instead, and we load it same-origin from the access-controlled Pages site the viewer is already signed in to. Freshness is per docs-build, which is why docs-publish.ts re-triggers that workflow after each push. license / issues / DocCI: public repo — shields.io renders these three live from the GitHub API. private repo — those API calls are unauthenticated and 404, so docs-publish.ts renders the same three to SVGs on the branch and we point at those. `private` and `repo_nwo` come from _data/ci.yml (written by the docs workflow) with a fall-back to jekyll-github-metadata for local builds. {%- endcomment -%} {%- comment -%} bare `default` (this Liquid has no allow_false): a public repo's ci.yml sets private:false, which falls through to site.github.private -- also false, so the result is still right. {%- endcomment -%} {%- assign priv = site.data.ci.private | default: site.github.private -%} {%- assign nwo = site.data.ci.repo_nwo | default: site.github.repository_nwo -%} {%- if priv -%} {%- assign base = '/generated/docs-data' | relative_url -%} {%- else -%} {%- assign base = 'https://raw.githubusercontent.com/' | append: nwo | append: '/generated/docs-data' -%} {%- endif -%}
